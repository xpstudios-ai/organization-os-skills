# Issue Template

Use this template for local or external tracker issues. Keep each
issue independently grabbable.

## Summary

One sentence describing the work and the user-visible or program-visible
outcome.

## Parent And Priority

Project or parent relationship, priority, labels, owner, and required tracker metadata.

## Context

Why this matters, where it fits, and links to the PRD, charter, parent issue, or
documentation source.

## Current Tranche

- Supersedes: prior brief or tracker record, or none.
- Starts after: consumed boundary, or initial state.
- Agent-executable work now:
- Already complete; do not replay:

## Scope

- In scope:
- Out of scope:

## Acceptance Criteria

- Plain bullet criteria only.
- Each criterion should be verifiable without rewriting the issue description.
- Include human-review requirements when the slice is not AFK-ready.

## Verification

Commands, review checks, adapter read-backs, or manual evidence required
to close the issue.

## Stop Condition (when applicable)

When a later human gate exists, name the exact boundary, prohibited actions,
and evidence that triggers re-triage. Use `ready-for-human` only when the next
action is human-only. Omit this section when the issue can safely proceed
through completion.

Record the exact tracker-mutation authority and the adapter's configured
holding, execution-claim, Agent Brief persistence, and read-back route in the
separate current Agent Brief.

## Risks, Dependencies, And Notes

Security, data, stakeholder, integration, migration, and blocker risks. Name
the unblocked frontier and relationships explicitly.

## Triage

State, category, owner, blockers, and whether the issue is ready for agent or
ready for human.
