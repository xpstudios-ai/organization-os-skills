# Short Engagement Body

Use only when an Engagement-body edit is requested or approved. An Engagement
is the entry point for its work. One **Opportunity Assessment** child page owns
the detailed assessment. Workspace holds persistent, reusable organizational
knowledge: guides, policies, processes and reference material. Engagement-specific
assessments, proposals, plans and substantial decision records belong under the
Engagement. This reference is not a separate
engagement-maintenance skill or automatic CRM workflow.

## Records

Place this section first in the page body, above Overview. Show canonical child
pages for the assessment and other existing engagement-specific documents,
such as a proposal, agreement, project plan or substantial decision record.
Include only pages that actually exist and label them by purpose. Update the
same assessment page as information changes; do not create a dated copy each time.

For externally stored documents or reusable Workspace knowledge, link the
existing original here rather than copying it into a child page. The Engagement
is the entry point even when the original lives in another system. Resolve and
preserve existing identities before an authorized move; do not create duplicate
pages or move a record merely because a link would be convenient.

## Overview

Two or three sentences about the durable purpose, problem and intended result.
If helpful, state a distinct decision needed from the other party. When scope
or price awaits internal approval, name that gate before describing an external
commitment. Omit the sentence when it merely repeats the Next Action property.
Use a durable theme for the title; lifecycle changes do not create a new record.

## Updates

Link dated meetings and material updates, newest useful item first, with one
link per record. Use a brief factual note only when no owning record exists.
Keep Meetings as completed snapshots and Interactions as brief contact history;
do not paste their full content or expand the body into an activity log. Future
meeting preparation belongs in a separate dated brief.

## Ownership And Size

Do not duplicate Owner, Key Contact, Stage, Status, Next Action, Value, time
totals, Evidence State, Fit Score, Qualification Verdict, Pursue, Assessment
Date or qualification-summary fields in the body. Properties own those fields;
Team and Contacts own people; Work Logs own time; the assessment child page
owns assessment rationale, evidence, gaps and gates. The body's Overview owns
only durable context and any distinct current decision; Records and Updates
own navigation. Keep a normal body below roughly 200 words, excluding link
labels. Empty template prompts must be replaced or omitted before delivery.

Routine decisions remain in their completed meeting or task record. Create a
separate child decision page only when its rationale needs a lasting reference.
Company-wide decisions that establish policy or a reusable process may belong
in Workspace; distinguish reusable knowledge from one engagement's activity.
Do not create an assessment for a noncommercial relationship to fill a section.

Manual/default Meeting and optional AI Meeting records keep their existing
table with the three columns `Topic`, `Outcome / Decision`, `Actions`.
Engagement setup and qualification remain optional after the first reviewed
meeting and owned action.

## Assessment Properties

An approved assessment save may update matching Qualification Verdict and
Assessment Date after verifying their native mapping. Evidence State and Pursue
remain unchanged unless explicitly instructed. Read back every authorized write.
The single child assessment belongs under Records; the parent carries navigation
and durable context without a duplicate qualification summary.
