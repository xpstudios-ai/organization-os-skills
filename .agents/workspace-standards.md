# Workspace Standards

## Planes And Ownership

- `skills/meeting-runner/` owns the existing public package variant. Preserve
  its privacy and three-column meeting contract.
- Shared kernels under `skills/` are pinned, complete directory copies of their
  declared upstream owner in `catalog.json`; change them through an upstream
  candidate or explicitly recorded variant, then verify complete parity.
- `skills/qualify-opportunity/` owns the new portable qualification format and
  short Engagement reference. Private source workflows inform the synthesis
  but are not public package dependencies or runtime entrypoints.
- `catalog.json`, `scripts/`, tests and package docs own inventory, digests,
  validation and project-local installation. Never reseal during validation.
- `distribution/` owns plugin identity, version, cleared selection and channel
  status. `scripts/build_plugin.py` derives complete plugin ZIPs and marketplace
  trees into new directories outside the source checkout. Generated payloads
  are release candidates; they never become an editable skill source.
- Consumer `.agents/skills/` copies and ownership receipts are generated by
  the installer. Verification uses disposable clean consumers only.
- Notion template, website, personal installation, organization consumers and
  live runtime state belong to their separate owners and approval scopes.

## Propagation

Update the local public source only. Preserve unrelated work; do not update
upstream checkouts, consumer/vendor trees or installed user-level skills.
Public main, tags, plugin channels, external records and deployment remain
gated. Complete local checks and direct review before proposing publication.
